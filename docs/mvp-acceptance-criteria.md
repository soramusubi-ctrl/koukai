# MVP受け入れ基準（精査版）

このドキュメントは、要件の曖昧さを減らし、実装完了判定を行うためのチェックリストです。

## 0. 用語定義

- **反応者**: 投稿に対して `欲しいよ` / `応援する` / `テスターになる` を行ったユーザー。
- **想定ターゲット**: 投稿者が投稿時に指定したカテゴリ（1〜3件）。
- **ズレ**: 想定ターゲット分布と実際反応分布の差。

## 1. 投稿機能

### 受け入れ基準
- 投稿フォームで以下が未入力なら保存不可:
  - アプリ名
  - 一言説明
  - 詳細説明
  - スクリーンショット2〜5枚
  - 想定ターゲット1件以上
  - 公開ステータス
- 投稿者本人のみ、投稿の編集・公開/非公開切り替えが可能。
- 一覧には `公開中` と `ベータ版` のみ表示（`アイデア段階` / `制作中` は詳細URL直アクセスのみ可でも可）。

## 2. 閲覧者プロフィール

### 受け入れ基準
- 初回反応時にカテゴリ選択を必須化（自由記述は任意）。
- 同一ユーザーはカテゴリを変更可能（履歴はMVPでは保持しない）。
- 未ログインユーザーは詳細閲覧のみ可、反応にはログイン必須。

## 3. 反応ボタン

### 受け入れ基準
- 同一ユーザーは同一投稿に対して同種リアクションを1回のみ実行可。
- `欲しいよ` は解除可能（トグル方式）。
- `応援する` はMVPでは無料リアクションとして扱う（決済なし）。
- テスター募集OFF投稿では `テスターになる` ボタンを非表示。

## 4. テスター募集

### 受け入れ基準
- 投稿者が募集ONにした場合、必須入力:
  - テスト内容
  - 対応端末
  - 募集人数（1以上）
  - テスト期間
  - 注意事項
- `テスターになる` は募集人数上限に達したら自動停止（または待機枠表示）。

## 5. 連絡リクエスト

### 受け入れ基準
- 連絡用途はプリセット選択必須（自由入力のみ不可）。
- 投稿者は `承認` / `拒否` を選択可能。
- 未承認状態では双方ともメッセージ送信不可。
- 承認後のみ、該当リクエストに紐づくスレッドで双方向メッセージ可。

## 6. 投稿者ダッシュボード

### 受け入れ基準
- 投稿ごとに以下を表示:
  - 欲しいよ数
  - 応援数
  - テスター希望数
  - 連絡リクエスト数
  - コメント数
- `欲しいよ` の属性分布をカテゴリ別比率で表示。
- 想定ターゲットとの差分を次のルールで表示:
  - 想定カテゴリの実績比率
  - 想定外カテゴリの上位3件

## 7. 最低限の安全・運営

### 受け入れ基準
- 投稿 / コメント / 連絡メッセージに通報導線がある。
- 連絡リクエストは同一投稿に対して同一ユーザーが24時間に5件以上送れない。
- 利用規約・免責の明示（成果保証しない）を初回登録時に同意取得。

## 8. 計測イベント（MVP）

### 必須イベント
- `app_created`
- `app_published`
- `reaction_want_clicked`
- `reaction_support_clicked`
- `tester_applied`
- `contact_request_sent`
- `contact_request_approved`
- `contact_request_rejected`

### 受け入れ基準
- すべてのイベントに `user_id`, `app_id`, `timestamp` を含む。
- ダッシュボード数値とイベント集計が日次で整合（±1%以内）。
