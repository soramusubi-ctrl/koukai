# Vercelデプロイ方針（現状）

## 結論（先に）

現時点のリポジトリは**仕様ドキュメントのみ**で、実行可能なWebアプリ実装はありません。
そのため、Vercelに出しても「アプリ本体」は動きません。

- **今すぐやるべきこと**: 実装を先に作る（Next.js推奨）
- **例外**: 仕様書を公開するだけなら、静的サイトとしてVercel公開は可能

---

## なぜそのままでは不十分か

このリポジトリには以下が未作成です。

- フロントエンド実装（画面・フォーム・ダッシュボード）
- API実装（投稿、反応、連絡リクエスト）
- DB接続・マイグレーション
- 認証

つまり、Vercelに接続しても本番体験は提供できません。

---

## 推奨デプロイ構成（MVP）

### 1) フロント
- Next.js (App Router)
- Vercel へデプロイ

### 2) DB
- Neon / Supabase / PlanetScale など

### 3) 認証
- Clerk / Auth.js / Supabase Auth

### 4) 画像
- Vercel Blob または S3互換ストレージ

### 5) 監視
- Vercel Analytics + Sentry（任意）

---

## デプロイ開始の最低手順（Next.jsの場合）

1. Next.jsプロジェクトを作成
2. MVP画面7枚をまず実装
3. `docs/data-model.md` に沿ってDBスキーマ作成
4. `docs/mvp-acceptance-criteria.md` の条件を満たす
5. Vercelへ接続し環境変数を設定して本番化

---

## Vercelに出す判断基準（Go/No-Go）

以下を満たしたら「出してよい」です。

- 投稿作成〜一覧表示〜詳細表示が通る
- `欲しいよ` が押せて、重複防止が効く
- 連絡リクエストが承認制で動く
- ダッシュボードで最低限の件数表示が出る
- 通報導線と利用規約導線がある
