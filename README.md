# Koukai（仮）

日本語圏の個人開発者向けに、**未完成のアプリ／試作ツールでも公開し、需要・熱量・協力者を集められる場**を目指すプロダクト仕様メモです。

## 一言で言うと

> 個人開発のアプリや試作ツールを日本語で公開し、
> 作り手が想定したターゲットと実際に反応した人のズレを見ながら、
> 「欲しいよ」「応援する」「テスターになる」を通じて需要・熱量・協力者を集めるサービス。

---

## コア価値

- ただの「いいね」ではなく、意味のある反応を集める
- 投稿者が想定したターゲットと、実際の反応層のズレを可視化する
- 一般ユーザー（非エンジニア）も参加しやすい体験にする
- 「未完成でも出してよい」空気をつくる

---

## MVPスコープ（Phase 1）

### 1) 投稿機能

必須入力:
- アプリ名
- 一言説明
- 詳細説明
- スクリーンショット（2〜5枚）
- 想定ターゲット（複数選択可）
- 作者コメント
- 公開ステータス

公開ステータス:
- アイデア段階
- 制作中
- ベータ版
- 公開中

制約:
- 外部リンク（GitHub / Web）は MVP では任意または非対応
- まずは「スクショ中心」で公開

### 2) 閲覧者プロフィール

軽量な自己申告属性:
- ママ・パパ
- 学生
- 教員
- 個人事業主
- 会社員
- クリエイター
- 個人開発者
- 農業関係
- 福祉・教育関係
- その他

追加情報:
- 自由記述（例: 3児の母 / 小学生の保護者 / 保育士 など）

### 3) 反応アクション

MVP必須:
- 欲しいよ（需要）
- 応援する（熱量）

MVP+候補:
- テスターになる
- 連絡したい / 協力したい

### 4) 応援（少額支援）

- 初期は未実装でも可
- 後続フェーズで固定金額（100 / 300 / 500 / 1000円）を検討
- 派手な投げ銭演出はしない

### 5) テスター募集

投稿単位で ON/OFF。
ONの場合の入力:
- テスト内容
- 対応端末
- 募集人数
- 想定対象者
- 期間
- 注意事項

### 6) 連絡機能（用途付きリクエスト）

自由DMではなく段階式:
1. 閲覧者が用途を選んでリクエスト送信
2. 投稿者が承認
3. 承認後のみ簡易メッセージ可能

用途例:
- テスターになりたい
- 話を聞きたい
- 協力したい
- 教育関係の立場で意見したい
- 支援職の立場で意見したい
- 導入相談したい

## ダッシュボード要件

表示指標:
- 欲しいよ数
- 応援数
- 応援総額（将来機能）
- テスター希望数
- 連絡リクエスト数
- コメント数
- 反応ユーザー属性分布
- 想定ターゲットとの差分（ズレ）

ズレ表示の例:
- 想定: ママ / 教員
- 実際(欲しいよ): ママ35%, 個人開発者30%, 教員15%, その他20%

---

## コメント設計方針

「すごい」で終わらせないため、テンプレ促進:
- どんな場面で使いたいか
- どんな立場で欲しいか
- 何があるともっと使いたいか
- 技術的改善提案（任意）

---

## やらないこと（MVP除外）

- 顔出し
- GitHub直リンク
- 外部サイト直リンク
- 本格通貨システム
- ランキング演出
- ライブ配信風投げ銭
- 高度検索
- SNSタイムライン化
- 専門家認証
- リアルタイムチャット
- 通話
- 高度レコメンド

---

## デザイン原則

- 日本語で親しみやすい
- 海外プロダクトのコピーになりすぎない
- かわいすぎず、冷たすぎない
- 主役は「人」より「アプリ」
- 未完成でも投稿しやすい心理的安全性

---

## 運営ポリシー（骨子）

- 接点は提供する
- 不適切行為には対処する
- やりとり内容・成果・専門性は過度に保証しない

## 次アクション提案

- `docs/mvp-user-flow.md` のユーザーフローに沿って画面遷移を確定
- `docs/data-model.md` の最小スキーマでAPI設計

- `docs/mvp-acceptance-criteria.md` の受け入れ基準を使って実装完了判定
- `docs/gap-analysis-spec.md` の算出仕様でダッシュボード表示を統一
- `docs/deploy-vercel.md` のGo/No-Go基準で公開判断
- まずは「欲しいよ」が使われるかの検証を最優先


## Vercelデプロイ

- プロトタイプとしてはデプロイ可能です。
- 実施前に `docs/vercel-deploy-checklist.md` を確認してください。


## ローカル起動

- `docs/run-local.md` に最短手順をまとめています。
- まず `make setup && make dev` を実行してください。


## GitHub同期

- GitHubに未接続の場合は `docs/github-sync.md` の手順で `origin` を追加してpushしてください。
- ワンコマンド: `./scripts/connect_github.sh <YOUR_GITHUB_REPO_URL> work`


## Windows向け

- PowerShellでの手順は `docs/windows-quickstart.md` を参照してください。


- PowerShellで `fatal: not a git repository` が出たら `docs/windows-quickstart.md` の対処手順を実行してください。

- Windowsでは `./scripts/push_work.ps1` でも `work` ブランチpushを簡略化できます。

- Vercelで空デプロイになる場合は `docs/vercel-troubleshooting.md` を確認してください。
